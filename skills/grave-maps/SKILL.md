# 무덤 4K 연습맵 찾기

파이프라인은 이 스킬 폴더의 `pipeline/`에 있다. 아래에서 `$G`는 이 스킬의 기본 폴더(이 SKILL.md가 있는 곳), `$W`는 작업 폴더다.
작업 폴더는 사용자의 현재 프로젝트 안에 만든다(예: `./grave-work`). 스킬 폴더 안에는 아무것도 쓰지 않는다.
명령은 모두 `python $G/pipeline/<스크립트> $W` 형태이고, 다시 돌리면 캐시로 이어서 진행한다.
설정·지표·파일 형식의 자세한 설명은 `reference.md`에 있다. 기준을 바꾸거나 새 지표를 만들 때는 먼저 그 파일을 읽는다.

## 준비물 (처음 한 번 확인)
- Windows x64, Python 3.10+, `pip install Pillow`(자켓 썸네일, 없어도 동작)
- .NET 10 런타임(`dotnet --list-runtimes`에 `Microsoft.NETCore.App 10.x`). 없으면 https://dotnet.microsoft.com/download/dotnet/10.0 에서 ".NET Runtime" 설치를 안내한다.
- osu! API 키: 예제 모드에는 필요 없다. 새로 수집하거나(01) 플레이 기록을 볼 때(05) 필요하다. 사용자가 osu! 웹 설정 → OAuth → "새 OAuth 애플리케이션"(콜백 URL은 비워도 됨)으로 만든 client id/secret을 `$W/secrets.json`에 넣게 한다. 키를 대화에 붙여 달라고 하지 말고 사용자가 파일에 직접 넣게 한다.

## 사용자에게 먼저 물을 것
1. **예제로 볼지, 새로 수집할지.** 예제는 2026-11 기준 무덤 4K 맵 1,182개를 계산까지 끝낸 데이터라 몇 분이면 페이지가 나온다. 새로 수집하면 osu!에서 다시 검색·다운로드·계산하므로 2~3시간 걸린다(대부분 다운로드 대기, 초당 1개 제한).
2. osu! 유저 id(친 맵 표시용, 선택)와 목표 dan raw(기본 11 = alpha. 12 = beta, 13 = gamma …).

## 흐름
| 단계 | 스크립트 | 하는 일 | 걸리는 시간(약 4,000 후보 기준) |
|---|---|---|---|
| 0 | `00_init.py $W [--example] [--user ID] [--dan 11]` | 작업 폴더, config.json, secrets.json 만들기. `--example`이면 예제 데이터 복사 | 수 초 |
| 1 | `01_search.py` | 무덤 맵셋 검색 → 후보 `cands.jsonl` | 5~10분 |
| 2 | `02_download.py` | 후보 .osu 다운로드 | 약 1시간+ |
| 3 | `03_calc.py` | 패턴 태그, 배속별 dan raw, 구간(REST/HARD) | 다운로드와 함께 돌리면 다운로드가 끝나고 수 분 |
| 4 | `04_refine.py` | 진입 배속을 0.05 단위로 다듬기 | 수 분 |
| 5 | `05_played.py` | (선택) 친 차트 목록 | 1분 안팎 |
| 6 | `06_classify.py` | 따닥이, 분류, 점수 → `final.json` | 1분 안팎 |
| 7 | `07_build.py` | 페이지 `grave.html` | 자켓을 처음 받으면 5분, 이후 수 초 |

- **예제 모드:** 0(`--example`) → (5) → 6 → 7.
- **새로 수집:** 0 → 1 → 2와 3을 동시에(2는 백그라운드로 돌리고 바로 3 시작. 3의 워커가 파일이 생기는 대로 계산한다) → 4 → 5 → 6 → 7. 긴 단계는 백그라운드로 돌리고 진행 상황(`dl.log`, `res3_*.jsonl` 줄 수)을 짧게 보고한다.
- 각 스크립트는 마지막에 요약을 출력한다. 06의 분류별 개수표는 사용자에게 그대로 보여준다.

## 결과 보여주기
- `$W/grave.html`은 파일 하나로 열리는 페이지다(자켓 내장, 3~4 MB): 분류 탭, 20개씩 더보기, 자켓·제목·난이도 이름·별점·패턴 태그·체력 태그.
- Artifact 도구가 있으면 그 파일을 Artifact로 publish해서 링크를 준다(아이콘 "list"). 없으면 브라우저로 열라고 경로를 알려준다(`start "" "$W/grave.html"`).
- 별점 = (점수 − 10) ÷ 10, 5개 만점. 점수가 10 미만인 맵은 페이지에서 빠진다.
- 분석·질문은 `final.json`을 읽어서 답한다(맵마다 진입 배속, raw, 따닥이 비율·주력 BPM, REST/HARD, 점수 항목이 다 들어 있다).

## 기준 바꾸기
사용자가 말로 요청하면 `$W/config.json`에 **바꿀 키만** 넣는다(나머지는 `pipeline/defaults.json` 기본값을 쓴다). 그다음 아래 표의 단계부터 다시 돌린다.

| 바꾸는 것 | config 키 | 다시 돌릴 단계 |
|---|---|---|
| 분류 이름·규칙·탭 순서, 분류 추가 | `classes` | 6, 7 |
| 따닥이 판정(BPM 범위, 허용 오차) | `tadak` | 6, 7 |
| 점수 항목·가중치, 체력맵 기준(70초) | `score`, `stamina_hard_s` | 6, 7 |
| 별점 환산, 페이지 제목, 친 맵 숨기기 | `page` | 7 |
| 목표 dan | `target_dan` | 3 (`--redo-no-curve`), 4, 6, 7 |
| 대상 패턴 태그(예: jumpstream 추가) | `patterns` | 3 (`--redo-no-curve`), 4, 6, 7 |
| 검색 조건(별·길이·즐겨찾기·매퍼 제한) | `search` | 1부터 전부 |

- `classes`는 위에서부터 처음 `when`이 참인 분류로 들어간다. 탭도 이 순서로 보인다. `when`은 파이썬 식이고, 쓸 수 있는 변수는 `reference.md` "분류 규칙 변수"에 있다.
- 예제 데이터에는 기본 패턴 태그(stream/tech/dumpstream/speedjack)에 맞고 alpha 근처를 통과한 맵만 들어 있다. 패턴을 넓히거나 목표 dan을 크게 낮추려면 새로 수집해야 한다고 알려준다. 목표 dan을 올리는 것은 예제로도 된다(4단계가 1.5x 위로 배속을 더 잰다).
- 변수로 표현할 수 없는 새 지표(예: 트릴 비율, 계단 비율, LN 밀도)는 `reference.md` "새 지표 추가"를 따라 `common.py`에 함수를 만들고, `06_classify.py`의 `env`에 넣은 뒤 `classes`에서 쓴다.

## 주의
- osu! 요청은 초당 1회 이하로 유지된다(`common.throttle`). 이 간격을 줄이지 않는다.
- 계산기(`calc/`)는 LazerSRebirth의 dan 판정기를 묶은 빌드다. 수정이 필요하면 저장소의 `calc-src/`를 보되, 다시 빌드하려면 원본 소스가 필요하다.
- `dotnet` 프로세스가 남아 있으면 `res3_*.jsonl`이 잠길 수 있다. 계산을 중단할 때는 `taskkill /F /IM dotnet.exe`.
